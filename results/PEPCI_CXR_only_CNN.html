Setup-01: PE Classification with only CXR Embeddings

Author

Awan Afiaz

Published

June 3, 2025

Introduction

A. The Clinical Problem

A pulmonary embolism (PE) occurs when a blood clot gets stuck in an artery in the lung, blocking blood flow to the lungs. Early detection and treatment are critical to reduce the risk of serious complications and death. The current diagnostic gold standard, the CT pulmonary angiogram (CTPA), is effective but exposes people to radiation, contrast, and increased cost.

B. The Proposed Solution and Overall Vision

This project aims to address these challenges through a systematic investigation of machine learning (ML) models capable of predicting PE from more readily available and safer data sources. By developing a predictive tool that leverages data from routine Chest X-Rays (CXR) and Electrocardiograms (EKG), we aim to create a powerful, low-cost screening and diagnostic aid. The overarching vision is to enhance early PE detection, thereby reducing morbidity and mortality in our patient populations. A successful model would simultaneously lessen the reliance on expensive CT scans, providing a safer and more efficient diagnostic pathway. This entire study is based on the publicly available MIMIC-IV dataset.

C. Initial Technical Approach: Embeddings and CNNs

We begin with an initial phase focused on pre-computed CXR embeddings to establish a performance baseline. For the radiography component, we will utilize the 4,096-dimensional feature vectors from the PhysioNet MIMIC-CXR dataset, which were generated by a state-of-the-art EfficientNet-L2 foundation model. This allows us to leverage deep representations of image abnormalities without the computational overhead of image processing. These rich CXR vectors will be combined with corresponding embeddings derived from EKG waveform data, and the initial models developed to fuse and interpret this data will be based on Convolutional Neural Network (CNN) architectures.

D. Advanced and Future Directions: Raw Data and Transformers

Building upon this foundation, the subsequent phase will engage directly with the raw data modalities. A multi-modal CNN architecture will be developed to process both the 2D pixel data from chest X-rays and the 1D time-series signals from electrocardiograms, allowing the model to learn features end-to-end. Looking forward, the project’s ultimate goal is to advance beyond conventional CNNs and explore the capabilities of transformer models.

1. Setup and Libraries

This document details the initial end-to-end process of building, training, and evaluating a deep learning model to predict Pulmonary Embolism (PE) from pre-computed Chest X-Ray (CXR) embeddings. The workflow begins with loading and parsing a complex .tfrecord data format, proceeds through data splitting and pre-processing, defines a sophisticated neural network architecture, trains the model, and concludes with a final, unbiased evaluation.

In the first step, we will set up our R environment. This involves loading all the necessary R packages that provide the functions we need for deep learning, data loading, and general data manipulation.

  • Inspect the file paths, which are specific to the original user’s machine.

  • Remove the user-specific prefix from the file paths to make them relative and portable.

3. TFRecord Parsing and Data Loading

We now need to read the actual embedding vectors, which are stored in a special binary format called .tfrecord.

  • Define a special “parser” function that teaches R and TensorFlow how to interpret the structure of our specific .tfrecord files.

  • Create a tfdatasets pipeline that applies this parser to every file path from our metadata.

  • Execute the pipeline, iterating through every file and converting the TensorFlow tensors into R-native objects.

  • Combine the list of vectors into a single large matrix.

  • Adjust the labels for R’s indexing system (from 0-1 to 1-2).

# Define a function to parse a single .tfrecord file.
parse_embedding_fn <- function(proto) {
  # Describe the structure of the data inside the .tfrecord file.
  features <- list(
    # The feature 'embedding' is stored as a variable-length list of floats.
    embedding = tensorflow::tf$io$VarLenFeature(dtype = tensorflow::tf$float32)
  )
  # Parse the binary record using the defined structure.
  parsed_features <- tensorflow::tf$io$parse_single_example(proto, features)
  # VarLenFeature creates a SparseTensor; convert it to a normal (dense) tensor.
  embedding_vector <- tensorflow::tf$sparse$to_dense(parsed_features$embedding)
  # Ensure the output is a flat 1D vector.
  tensorflow::tf$reshape(embedding_vector, shape = list(-1L))
}

# Create a dataset pipeline object from the filepaths.
tf_dataset <- tfrecord_dataset(embedding_metadata$filepath) |>
  # Apply our parsing function to each file in the dataset.
  dataset_map(parse_embedding_fn)

# Execute the pipeline and load all embeddings into R.
# reticulate::iterate calls the tensor's .numpy() method to convert it to an R object.
embedding_list <- reticulate::iterate(tf_dataset, f = function(x) x$numpy())
# Combine the list of individual embedding vectors into a single matrix.
all_embeddings <- do.call(rbind, embedding_list)

# Get the labels vector and add 1 to convert from 0/1 to 1/2.
# This is required for R's 1-based indexing in the torch loss function.
outcome_labels <- embedding_metadata$label + 1

This chunk is the result of our extensive debugging and represents the correct way to load this specific dataset.

  • parse_embedding_fn: This function is the instruction manual for reading a single file. We discovered through debugging that the data is stored as a VarLenFeature (variable-length feature). Inside the function, we parse the file, convert the data from its special “sparse” format to a regular “dense” vector, and reshape it to ensure it’s a flat list of numbers.

  • tfrecord_dataset(): This creates the initial dataset object, which is essentially a list of file paths.

  • reticulate::iterate(): This is the key function that executes the pipeline. It loops through every parsed record and uses the .numpy() method to convert the TensorFlow tensor into an R-friendly format.

  • do.call(rbind, ...): This is an efficient R function for taking a list of vectors and stacking them together row-by-row to create our final all_embeddings matrix.

  • + 1: We add 1 to the labels (0, 1) to turn them into (1, 2). This is critical because torch in R expects class indices to start at 1, not 0.

4. Data Splitting

To build a reliable model, we must separate our data into distinct sets.

  • Training Set (70%): The data the model learns from.

  • Testing Set (15%): Data used during training to monitor for overfitting.

  • Validation Set (15%): The “lockbox” data, used only once at the very end for a final, unbiased performance evaluation.

cat("--- Splitting Data ---\n")
--- Splitting Data ---

# Shuffle indices to ensure random distribution of data across splits.
shuffled_indices <- sample(num_samples)

# Define the size of each dataset split.

test_size <- floor(0.15 * num_samples)

# Get the indices for each set from the shuffled list.

val_indices <- shuffled_indices[(train_size + test_size + 1):num_samples]

Code Explanation

  • torch_tensor(): The primary function for converting R objects to torch tensors. The dtype = torch_long() is important for the labels, as classification loss functions expect integer-type labels.

  • scorch_create_dataloader(): This scorcher function simplifies the creation of a dataloader. A batch_size = 32 means the model will look at 32 samples at a time before updating its weights.

6. Model Architecture Definition

Now we define the “brain” of our operation—the neural network itself. This is a moderately complex architecture designed to be powerful enough for this task. It is organized into logical blocks and uses Batch Normalization and Dropout.

cat("\n--- Building Balanced Model Architecture ---\n")

--- Building Balanced Model Architecture ---
# Define a moderately complex neural network architecture using a scorcher pipeline.
scorch_model <- dl |>
  initiate_scorch() |>
  # === INPUT PROCESSING ===
  # Expands features and applies immediate regularization.
  scorch_layer("linear", in_features = embedding_dim, out_features = 512) |>
  scorch_layer("batch_norm1d", num_features = 512) |>
  scorch_layer("relu") |>
  scorch_layer("dropout", p = 0.2) |>
  
  # === FEATURE EXTRACTION BLOCK 1 ===
  # Uses a sigmoid 'gate' to help the model select important features.
  scorch_layer("linear", in_features = 512, out_features = 384) |>
  scorch_layer("batch_norm1d", num_features = 384) |>
  scorch_layer("relu") |>
  scorch_layer("linear", in_features = 384, out_features = 384) |>
  scorch_layer("sigmoid") |>
  scorch_layer("dropout", p = 0.3) |>
  
  # === FEATURE EXTRACTION BLOCK 2 ===
  # Uses tanh activation to bound features between -1 and 1.
  scorch_layer("linear", in_features = 384, out_features = 256) |>
  scorch_layer("batch_norm1d", num_features = 256) |>
  scorch_layer("relu") |>
  scorch_layer("linear", in_features = 256, out_features = 256) |>
  scorch_layer("batch_norm1d", num_features = 256) |>
  scorch_layer("tanh") |>
  scorch_layer("dropout", p = 0.4) |>
  
  # === CLASSIFICATION HEAD ===
  # Reduces features down to the final class outputs.
  scorch_layer("linear", in_features = 256, out_features = 128) |>
  scorch_layer("batch_norm1d", num_features = 128) |>
  scorch_layer("relu") |>
  scorch_layer("linear", in_features = 128, out_features = 64) |>
  scorch_layer("batch_norm1d", num_features = 64) |>
  scorch_layer("relu") |>
  scorch_layer("dropout", p = 0.3) |>
  
  # Final Output Layer: Produces raw scores (logits) for our 2 classes.
  scorch_layer("linear", in_features = 64, out_features = 2)

# Compile the defined architecture into a trainable torch model.
compiled_scorch_model <- compile_scorch(scorch_model)

Code Explanation

This scorcher pipeline defines a deep neural network layer-by-layer.

  • scorch_layer("linear", ...): A standard fully-connected layer. in_features must match the output of the previous layer, and out_features defines the size of the next layer.

  • scorch_layer("relu"): The main activation function, allowing the model to learn non-linear patterns.

  • scorch_layer("batch_norm1d", ...): Normalizes the outputs of the previous layer, which helps stabilize and speed up training.

  • scorch_layer("dropout", p = ...): A regularization technique that randomly sets a proportion (p) of neuron activations to zero during training to prevent overfitting.

  • compile_scorch(): This finalizes the model definition and prepares it for training.

Summary of the Model Architecture

The model is a deep, feed-forward neural network designed to classify Pulmonary Embolism (PE) risk from high-dimensional (4096) CXR embedding vectors. The architecture follows a sophisticated “funnel” design, progressively reducing the dimensionality of the features while using a combination of modern techniques to stabilize training and prevent overfitting. It is organized into distinct logical blocks:

1. Input Processing Block (4096 → 512 features)

This initial block serves to compress the large, sparse input embedding into a more manageable and dense feature representation.

  • linear(4096, 512): The first layer performs a crucial transformation, reducing the feature dimension from 4096 to 512. This forces the model to create a dense summary of the initial information.
  • batch_norm1d: Immediately follows the linear layer to stabilize its output, which is critical when dealing with such a large input dimension.
  • relu: The standard activation function introduces non-linearity, allowing the model to learn complex patterns.
  • dropout(p=0.2): A light dropout is applied. This provides initial regularization without discarding too much potentially valuable information from the input embedding.

2. Feature Extraction Block 1 (512 → 384 features)

This block continues to refine features and introduces a “gating” mechanism to help the model learn which features are most important.

  • linear & relu: The network continues to process and transform the 512 features into a 384-feature space.
  • sigmoid Gate: A unique feature of this block is a linear layer followed by a sigmoid activation. This sigmoid function squashes its output to a range between 0 and 1, effectively acting as a learned “gate” that can scale down the importance of less relevant features before passing them to the next stage.
  • dropout(p=0.3): A slightly higher dropout rate is applied after the gating mechanism for regularization.

3. Feature Extraction Block 2 (384 → 256 features)

This block further distills the features and introduces a “bounding” mechanism.

  • linear & relu: The feature space is further reduced from 384 to 256 dimensions.
  • tanh Activation: This activation function bounds the feature values to a range between -1 and 1. This “centering” of the data can help stabilize learning in the subsequent layers.
  • dropout(p=0.4): The dropout rate is increased again. As the features become more abstract and complex, we can apply stronger regularization to ensure the model is learning generalizable patterns.

4. Classification Head (256 → 64 features)

This is the final stage of feature processing, where the network funnels the highly abstract features into a compact representation just before the final decision.

  • Two linear + relu Blocks: The feature space is decisively reduced from 256 to 128, and then to a final, compact set of 64 features.
  • dropout(p=0.3): One last application of dropout provides final regularization before the output layer.

5. Output Layer (64 → 2 features)

This is the final decision-making layer of the model.

  • linear(64, 2): This layer takes the final 64-feature vector and produces exactly two raw numbers (logits). Each number represents the model’s calculated score for one of the two classes (Class 1: No PE, Class 2: PE). These scores are then fed into the loss function during training and the argmax function during evaluation.
