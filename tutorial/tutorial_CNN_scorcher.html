Understanding Convolutional Neural Networks with scorcher and Internet Cats

Author

Awan Afiaz

Breathe in, breathe out. We’re going to embark on a journey to understand a cool R package called scorcher. But before we dive into the code, we’ll start with the very basics of how a computer can “see” and “understand” images, which is the magic behind Convolutional Neural Networks (CNNs).

Part 1: The Building Blocks - Understanding How Computers “See”

Imagine you’re teaching a child to recognize a cat. You wouldn’t just show them one picture and expect them to get it right every time. You’d show them many different cats: big ones, small ones, fluffy ones, sleeping ones, and so on. In a way, this is how we train a computer.

A Convolutional Neural Network (CNN) is a type of computer program designed to recognize patterns in images. Think of it as a series of filters and transformations that help the computer focus on the important features of an image, just like you might point out a cat’s pointy ears or long whiskers to a child.

What’s in a Picture? Pixels!

To a computer, an image is just a grid of numbers. Each number represents the color of a tiny dot called a pixel. For a simple black and white image, a pixel might be 0 for black, 255 for white, and shades of gray in between. For a color image, each pixel would have three numbers representing the amount of red, green, and blue (RGB).

Our goal is to teach the computer to look at this grid of numbers and say, “That’s a ‘7’!” or “That’s a cat!”.

The Core Idea: Convolutions

This is the “C” in CNN and the most important concept to grasp. A convolution is a fancy word for applying a filter to an image. But what is a filter?

Imagine you have a tiny magnifying glass that can only see a small 3x3 square of pixels at a time. This magnifying glass has a special pattern on it. Maybe it’s designed to light up when it sees a vertical edge. This special magnifying glass is our filter (also called a kernel).

Here’s how it works:

  1. Slide: We take our filter and slide it over every single 3x3 patch of our image, from left to right, top to bottom.

  2. Calculate: At each position, we do some simple math. We multiply the numbers in our filter by the pixel values in the image patch underneath it and then add them all up.

  3. Create a Feature Map: The result of this calculation for each position gives us a new grid of numbers. This new grid is called a feature map. This map highlights where the feature our filter was looking for (like a vertical edge) appeared in the original image.

We can have many different filters, each looking for a different simple feature:

  • A filter for horizontal edges.

  • A filter for diagonal edges.

  • A filter for curves.

By applying several of these filters, we get a stack of feature maps, each one telling us about the presence of a different basic shape in the image.

Making Sense of the Features: ReLU and Pooling

After the convolution, our CNN does a couple more things to process the information.

  • ReLU (Rectified Linear Unit): This sounds complicated, but it’s super simple. It’s an “activation function” that goes through our feature map and changes all the negative numbers to zero. Think of it as enhancing the important features (the positive numbers) and getting rid of the noise (the negative numbers).
  • Pooling: Our feature maps can be quite large. To make them more manageable and to focus on the most important information, we use pooling. The most common type is max pooling. Here’s how it works:
    1. We take a small window (say, 2x2 pixels) of our feature map.
    2. We find the largest number within that window.
    3. We keep only that largest number and discard the rest.
    4. We slide our window across the entire feature map, creating a new, smaller feature map.

This process effectively summarizes the features in a region. It makes our network more robust because even if a feature moves slightly in the image, the pooled feature map will likely still capture its presence.

Putting It All Together: The CNN Architecture

A typical CNN is a sequence of these layers:

  1. Convolution Layer: Applies filters to the input image to create feature maps.
  2. ReLU Layer: Activates the features.
  3. Pooling Layer: Downsamples the feature maps to make them smaller and more focused.

We can stack these sets of layers multiple times. The early layers learn to recognize simple features like edges and corners. The later layers combine these simple features to learn more complex patterns, like eyes, noses, or the shape of a number.

Finally, at the very end of the network, we have a “fully connected layer” that takes the high-level features and makes the final prediction: “This is a cat with 98% confidence.”

Part 2: scorcher - Making CNNs Easy in R

Now that we have a feel for what a CNN is doing under the hood, let’s look at the scorcher package. scorcher is an R package that makes it easier to build and train these complex networks without getting bogged down in the nitty-gritty details. It acts as a friendly interface to a powerful deep learning library called torch.

Let’s break down the MNIST example step-by-step.

# First, you'd need to install the package from GitHub
# install.packages("pak")
# pak::pak("jtleek/scorcher")

The Goal: Classifying Handwritten Digits

The example in the scorcher uses the famous MNIST dataset. This is a collection of 70,000 small, black and white images of handwritten digits (0 through 9). The goal is to build a CNN that can look at one of these images and correctly guess which digit it is.

Step 1: Preparing the Data

library(scorcher)
library(torch)
library(torchvision)

# Training Data
train_data <- mnist_dataset(
  root = tempdir(),
  download = TRUE,
  transform = transform_to_tensor
)

x_train <- torch_tensor(train_data$data, dtype = torch_float()) |> torch_unsqueeze(2)
y_train <- torch_tensor(train_data$targets, dtype = torch_long())
  • library(torch) and library(torchvision): We load the necessary libraries. torch is the core deep learning engine, and torchvision provides easy access to common datasets like MNIST and tools for working with images.
  • mnist_dataset(...): This function downloads the MNIST dataset to a temporary directory (tempdir()) if you don’t already have it.
  • transform = transform_to_tensor: This is a crucial step. It tells R to convert the images from their standard format into tensors. A tensor is the fundamental data structure in torch. Think of it as a multi-dimensional array or matrix that’s optimized for the kind of math we do in deep learning.
  • x_train and y_train: We separate our data into two parts:
    • x_train: These are the images themselves (the input). We convert them to torch tensors of floating-point numbers. The torch_unsqueeze(2) part adds an extra dimension to our data, which is needed for the convolutional layers to know that we’re dealing with grayscale images (which have one color channel).
    • y_train: These are the labels for each image (the correct answers). For each image in x_train, there’s a corresponding number in y_train that tells us what digit it is.

Step 2: Creating a Data Loader

# Create the Dataloader
dl <- scorch_create_dataloader(x_train, y_train, batch_size = 500)
  • scorch_create_dataloader(...): When we train a neural network, it’s often too slow to show it all 60,000 training images at once. Instead, we show it smaller batches of images. This dataloader is a handy tool that takes our training data and prepares it to be fed to our model in these batches.
  • batch_size = 500: This tells the dataloader to give our model 500 images at a time. The model will look at these 500 images, make its predictions, see how well it did, and then learn from its mistakes before moving on to the next batch of 500.

Step 3: Defining the Neural Network with scorcher

This is where the magic of scorcher really shines. We define our entire CNN architecture using a clean, readable pipeline.

# Define the Neural Network
scorch_model <- dl |>
  initiate_scorch() |>
  scorch_layer("conv2d", in_channels = 1, out_channels = 32, kernel_size = 3) |>
  scorch_layer("relu") |>
  scorch_layer("conv2d", in_channels = 32, out_channels = 64, kernel_size = 3) |>
  scorch_layer("relu") |>
  scorch_layer("max_pool2d", kernel_size = 2)

Let’s break this down layer by layer:

  • initiate_scorch(): This starts the process of building our model.
  • scorch_layer("conv2d", ...): This adds our first 2D convolutional layer.
    • in_channels = 1: This tells the layer that our input images have one color channel (because they are grayscale).
    • out_channels = 32: This means we want this layer to learn 32 different filters. It will produce 32 feature maps.
    • kernel_size = 3: This specifies that each filter will be a 3x3 square.
  • scorch_layer("relu"): This adds the ReLU activation function we talked about earlier.
  • scorch_layer("conv2d", ...): This is our second convolutional layer.
    • in_channels = 32: The input to this layer is the output of the previous one, which had 32 channels (our 32 feature maps).
    • out_channels = 64: This layer will learn even more complex features, creating 64 new feature maps.
  • scorch_layer("relu"): Another ReLU activation.
  • scorch_layer("max_pool2d", kernel_size = 2): This adds a max pooling layer with a 2x2 window to downsample our feature maps.

Behind the scenes, scorcher will automatically add the final layers needed to take these feature maps and produce a prediction for our 10 digit classes (0-9).

  • fit_scorch(...): This is the command that actually starts the training process.
  • loss = nn_cross_entropy_loss: A loss function is a way of measuring how wrong our model’s predictions are. nn_cross_entropy_loss is a standard and effective loss function for classification problems like this one. During training, the model will try to adjust its internal parameters (the patterns in its filters) to make the value of this loss function as low as possible.
  • num_epochs = 10: An epoch is one full pass through the entire training dataset. Here, we’re telling the model to go through all the training images 10 times.
  • verbose = T: This tells the function to print out progress updates as it trains, so we can see the loss going down with each epoch.

The output you see shows the loss decreasing over the 10 epochs, which means our model is getting better and better at classifying the digits!

Part 3: Alternative Approaches and Deeper Intuition

Let’s play with the scorcher model to build a more intuitive understanding.

What if we use fewer filters?

# A simpler model
simpler_model <- dl |>
  initiate_scorch() |>
  scorch_layer("conv2d", in_channels = 1, out_channels = 8, kernel_size = 3) |> # Only 8 filters
  scorch_layer("relu") |>
  scorch_layer("max_pool2d", kernel_size = 2)

In this version, the first convolutional layer only learns 8 filters instead of 32. This model would be faster to train but might not be as accurate because it’s not learning as many different features from the images. It has a less nuanced “vocabulary” of shapes to look for.

What if we use larger filters?

# A model with larger filters
larger_filter_model <- dl |>
  initiate_scorch() |>
  scorch_layer("conv2d", in_channels = 1, out_channels = 32, kernel_size = 5) |> # 5x5 filters
  scorch_layer("relu") |>
  scorch_layer("max_pool2d", kernel_size = 2)

Here, we’re using 5x5 filters. A larger filter can capture more complex patterns in a single step but is also computationally more expensive. The choice of filter size is a trade-off between capturing detail and computational efficiency.

By experimenting with these parameters, you can start to see how different choices in the CNN architecture affect the model’s ability to learn and its final performance. The scorcher package makes this kind of experimentation incredibly straightforward and accessible, even for those who are new to the world of deep learning.
